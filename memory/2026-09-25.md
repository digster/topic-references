## Method (reusable)

- **Extract, then read.** A stdlib `html.parser` script dumped every `.resource-item`
  (section, title, href, source, level, note, links nested in the note) to a per-page text
  digest plus JSON. Reading 16 digests is far faster than reading 400 KB of HTML, and the
  JSON drives every later check. 571 rows total, 519 unique external URLs.
- **Live sweep of every external URL**: GET (not HEAD), follow redirects, record status,
  final URL, content type, byte size and `<title>`. 450 × 200, 69 other.
- **Three passes over the 200s**, because a 200 proves nothing on its own:
  1. *redirected to a different host/path* → catches moved docs and retired courses;
  2. *title keyword or tiny HTML body* → soft-404 candidates;
  3. *word overlap between the listed title and the live `<title>`* → catches pages that
     now show **different content**. This pass found both wrong-content links below;
     no status-code check would have.
- **Re-check the non-200s by host type** before calling anything dead:
  - YouTube 429 → `https://www.youtube.com/oembed?format=json&url=…` (all 30 IDs fine);
  - GitHub 403 to scripted clients → `git ls-remote https://github.com/<owner>/<repo> HEAD`
    (all 17 repos fine);
  - connection failures → DNS-over-HTTPS (`https://dns.google/resolve?name=<host>&type=A`)
    to separate a genuinely dead domain (`"Status":3` = NXDOMAIN) from a proxy or firewall
    problem.
- **Verify every suggested addition too.** ~100 candidate resources were checked (arXiv
  titles, publisher pages, oEmbed) before being recommended. Two books were misdated and
  several guessed publisher URLs were wrong; see *Verified candidates* for the good URLs.
- **Grep the site before claiming "nothing covers X".** Use case-sensitive, word-bounded
  patterns: a case-insensitive `ViT` matches "activity", `ETF` matched a substring, and
  `GNN` matched a YouTube ID (`7xTGNNLPyMI`).

## Host quirks learned this session

- **Penguin UK routes by ISBN, not by the numeric ID,** and reuses IDs: the shipped
  `/books/442174/…/<isbn>` went wherever the ISBN pointed, and ID 442174 alone now maps to
  an unrelated book. Verify the ISBN, not just the 200.
- **Christie's recycles lot URLs.** Link the `onlineonly.christies.com/s/<sale>/<lot>/<id>`
  form for online sales.
- **Headless Chromium doesn't trust the session proxy's CA** (`ERR_CERT_AUTHORITY_INVALID`).
  Don't work around it by disabling TLS verification; use curl + oEmbed/`git ls-remote`/DoH.
- `z.cash` answers scripts with **202 and a ~198-byte body** (same bot-challenge shape as
  `global.oup.com`).
- `physics.nyu.edu` (the Sokal page) fails curl with an incomplete TLS chain. It's fine in
  browsers (AIA fetching); not a dead link.
- `amazon.com`, `khanacademy.org`, `kaggle.com`, `defillama.com` and `medium.com` return
  bot challenges to scripts; all are live.

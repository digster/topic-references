## The order, and where it came from

The clusters were **read off the site's own cross-link graph, not invented**. One command
produces the whole justification:

```sh
for f in topics/*.html; do echo "--- $(basename $f .html)"; \
  grep -o 'href="[a-z0-9-]*\.html"' "$f" | sed 's/href="//;s/\.html"//' | sort -u | tr '\n' ' '; echo; done
```

It shows exactly three components: the 6 AI pages (complete graph), the 7 crypto pages
(hub-and-spoke on `blockchain-and-cryptocurrency`), and two degree-zero pages. Plus the single
`decentralized-finance` ↔ `starting-a-new-bank` edge bridging crypto to the bank page.

| # | Cluster | Order |
|---|---|---|
| 1 | AI & ML (6) | AI → ML → Deep Learning → Transformers → LLMs → GenAI |
| 2 | Crypto (7) | Blockchain → Ethereum → L2 → ZK → NFTs → DAOs → DeFi |
| 3 | Finance (1) | Starting a New Bank |
| 4 | Standalone (2) | Data Structures and Algorithms, Structuralism and Post-Structuralism |

Within a cluster: **learning path**, parent field first — the same principle `CLAUDE.md` already
mandates for resources *inside* a page, now applied to the grid.

**Two adjacencies are load-bearing** and should survive future edits: L2 next to ZK (the crypto
family's strongest edge) and DeFi immediately before the bank page (the site's only cross-family
edge, now visible as a side-by-side pair).

## Why a flat reorder and not group headings

Headings were the obvious first instinct and are **wrong here**. A `<h2>` inside `#topic-grid`
becomes a grid item, and the filter only toggles `.topic-card` — so any search would strand
headings above hidden cards. Fixing that means editing the inline `<script>`, which `CLAUDE.md`
explicitly forbids ("it reads cards generically"). Cluster boundaries are **HTML comments**
instead: comment nodes create no boxes, so they cannot disturb the grid, and they carry the
intent for the next editor. Reordering a flat grid gets the grouping for free.

Corollary worth remembering: **the filter is order-independent by construction.** It pairs
`cards[i]` with `haystacks[i]`, so reordering the DOM reorders both together. Side benefit —
filtered results now come back in cluster order too (`attention` → Deep Learning, Transformers,
LLMs).

## Grid geometry — measured, not assumed

`--maxw: 880px` minus `24px` padding each side = **832px** content column. With
`repeat(auto-fill, minmax(250px, 1fr))` and `gap: 22px`: 3×250+2×22 = 794 ≤ 832 but
4×250+3×22 = 1066 > 832, so **3 columns on desktop**, 2 when narrower, 1 below the 540px
breakpoint. Confirmed in the browser (`gridWidth: 832`, `columns: 3`).

This mattered for choosing the order. Leading with the 6-card AI cluster makes it fill rows 1–2
exactly at 3 columns, and at **2 columns every cluster boundary lands on a row boundary**
(AI = rows 1–3, crypto = rows 4–6 + DeFi, `DeFi | Bank` = row 7, the two standalones = row 8).
An order that only groups well at one width would have been fragile — linear adjacency is the
property that actually survives reflow, and the row alignment is a bonus that will shift as soon
as a 17th topic is added.
